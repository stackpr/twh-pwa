Settings file

One plain text file — troop-settings.txt — holding the troop name, report parameters, the chart of accounts, and the balance-sheet snapshots. Open it in Notepad, TextEdit or any other text editor to change it, then load it back here. It contains no scout names and no transactions, so it is safe to hand to a successor — this file plus a fresh TroopWebHost export is everything they need.

Fiscal year and budget

The monthly income statement covers the fiscal year to date. Choosing Not set gives the older behaviour instead — a rolling window of the last Months shown months — and turns budgets off, since a budget needs a period to be a budget for.

A budget for one fiscal year, entered here and nowhere else — TroopWebHost has no record of it, so the settings file is the only copy. It appears on the monthly income statement as Budget and Remaining columns; both are omitted entirely when nothing is budgeted.

Budget a whole category, or individual funds within it, or both — a category figure covers whatever in that category you did not budget by fund. Enter every figure as a positive number, the way it prints on the statement: revenue as revenue, spending as spending.

Clear cache

Everything this app remembers — the troop name, the report parameters, the chart of accounts, the balance-sheet snapshots, and the offline copy of the app itself — is stored in this browser, on this computer. Nothing is held on a server, so nothing here can be recovered once cleared.

On a shared or borrowed computer, clear it before you walk away. The next person to open this browser would otherwise see your troop name, chart of accounts, and published balance-sheet totals.

Download the settings file from the Settings tab first if you want to keep the chart of accounts and the snapshots. That file is the only copy.

Or clear one thing at a time

Clear snapshots drops the published balance-sheet figures. Reset settings restores the example chart of accounts and the default parameters, keeping snapshots. Purge offline app cache removes the installed copy of the app and unregisters its service worker, keeping settings and snapshots; use it if a deployment looks stale.

Transaction data is not on this list because it is never stored. The export is read into memory, and scout names are hashed and the originals discarded before anything else sees them. Closing the page ends it.

What this does

It reads a TroopWebHost transaction export and produces three printable reports — a Balance Sheet, an Event Income statement, and a Monthly Income statement — without pivot tables or hand-maintained formulas. Every figure is a sum over the same set of transaction legs, so the reports cannot disagree with each other.

Monthly routine

  1. In TroopWebHost, run Export All Transactions to Excel. It produces a CSV despite the name.
  2. On the tab, drop the file on the target.
  3. On the tab, read the Reconciliation panel first. The account, fund and transaction-type counts should match last month; a jump in single-leg entries means something unusual was posted.
  4. Set Past events shown so the Event Income statement fits one page. It is a page-fit control only — the totals never change with it.
  5. Print each report and save as PDF.
  6. Press Capture snapshot at this date, then download the settings file from the tab and keep it with the PDFs.

First run, and handover

The app ships with an example chart of accounts, which will not match your troop. You do not have to build yours by hand: import your export and every fund and troop account it contains is added for you, each with a guessed classification that the Import tab then asks you to confirm. Correct anything wrong there — the reports update as you do — and download the settings file to keep the result. The Settings tab lists the same funds and accounts, where you can add one, remove one, or move it to another category by hand. The category names themselves are fixed: they are the sections of the income statement.

A fund or account that appears in the export you have loaded cannot be removed — its transactions would have nothing to classify them. And a fund carrying a budget asks where that budget should go before it leaves, so the year's total ends up where it started.

The same review lists anything in your settings the export never mentions, which is usually last year's chart of accounts, and offers to remove it. Removing changes no figure. Nothing is ever classified behind your back: while any guess is unconfirmed, a warning sits above the reports.

The settings file plus a fresh export is everything a successor needs. It holds no scout names, no individual balances, and no transactions, so it is safe to email; a transaction export never is.

Fiscal year and budget

On the tab, set Fiscal year starts to the month your troop's year begins. It starts at January. The monthly income statement covers the fiscal year to date, which is the period a budget is written against; choosing Not set gives a rolling twelve months instead and turns budgets off.

The same tab takes a budget for the year: a figure for a whole category, or for individual funds within it, or both — a category figure covers whatever you did not budget by fund. The statement then shows Budget and Remaining columns, and shows neither when nothing is budgeted. A line you left blank stays blank rather than printing as zero, because a blank is not the same as a decision to spend nothing. Budgets exist only here — TroopWebHost has no record of them — so the settings file is the only copy.

Why some things look the way they do

The balance sheet is not filtered by the as-of date. Event fees are dated to the event, so a fee for a future event has already moved a scout's balance. Filtering it out would understate what the troop owes. The deferred position appears instead on the Other Future Events (Net) line.

Only the balance sheet is snapshotted. The income statements are period reports and are recomputed every time; if a back-dated entry lands, they move, and that is correct. The balance sheet is the one thing published as a point-in-time position, so it is frozen — and when the recomputed figures differ from a snapshot, the app says so rather than quietly rewriting what was published.

Reports are computed, never stored. Reload the page and they are gone until the export is dropped again. That is deliberate: a financial report on disk goes stale, and a stale one gets circulated.

Privacy

The app makes no network requests once loaded: no analytics, no fonts, no third-party scripts. The export is read locally through the browser's file API and never becomes a network request. Scout names are hashed the moment the file is parsed and the originals discarded. Nothing about your troop appears in the web address, so nothing leaks through browser history or a shared link.

Configuration and whole-troop snapshot totals are kept in this browser so you do not re-enter them monthly. On a shared computer, clear them from the tab when you are done.

Installing

On Chrome, Edge or Android an Install for offline use button appears at the top once the browser decides the app is installable. On iPhone or iPad, use Share → Add to Home Screen. Installed, it works with no connection at all.

Scout names are hashed at parse time and the originals are discarded before anything else reads them. No transaction data is written to storage or sent anywhere, by any code path. See the README for conventions.
